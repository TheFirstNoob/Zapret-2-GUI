# YouTube: «страница открывается, видео не грузится» — расследование 2026-11

> Статус: первичное расследование завершено 2026-11-14 (актуальный релиз — 0.10,
> 0.11 в подготовке). Это курируемая выжимка; сырые измерения — локально в
> `_analysis/youtube-stall/` (gitignored, не коммитить: там IP/провайдер и
> локальные детали конкретной сети).

## 1. Симптом

У части пользователей 0.10 YouTube открывается (страница, превью, поиск), но
видео не воспроизводится — бесконечный спиннер. WARP обходит проблему.
Гипотезы владельца: ужесточение РКН/ИИ-детекции либо новый алгоритм рекламы
YouTube. На тестовой сети владельца симптом воспроизведён в лабораторных
условиях (см. §2.3–2.4).

## 2. Что установлено (сводка; уверенность указана)

### 2.1 Плеер YouTube 2026 — SABR-only (высокая)

В `ytInitialPlayerResponse` браузерного WEB-клиента 14–26 adaptiveFormats,
но ни у одного нет прямого `url`. Единственный источник медиа —
`streamingData.serverAbrStreamingUrl` (`.../videoplayback?...&sabr=1`, один
POST-поток). Классических per-format URL для desktop-браузера больше нет:
старые пробы «скачать videoplayback GET-ом» не показательны, а диагностика
видео должна проверять SABR-поток (POST) и/или QUIC/h3.

### 2.2 Видео-узлы — локальные GGC (высокая)

Все `rr*---sn-...googlevideo.com`, которые выдаёт плеер, на проверенной сети
резолвились в локальные GGC-кэши провайдера. Узел — настоящий Google:
сертификат `*.googlevideo.com` (Google Trust Services), HTTP/80 отвечает
`Server: gvs 1.0` и Google-страницей 404; ICMP и TCP 80/443 живые. Подмены
DNS/заглушки не обнаружено (системный резолвер = DoH Cloudflare/Google).

### 2.3 Класс «GGC TLS-CH blackhole» — route-class (высокая)

К локальным GGC-узлам:
- TCP-коннект — ОК, ICMP — ОК, HTTP/80 — ОК;
- TLS-хендшейк детерминированно НЕ проходит для видео-SNI (`rr*.googlevideo.com`,
  `www.youtube.com`), таймаут 4–6 с;
- TLS проходит только для «белого» SNI (`google.com` и подобные) и только
  до того же узла;
- **fake+multisplit нашего desync этот маршрут НЕ лечит** — одинаково с обходом
  и без него;
- тот же SNI на не-GGC/глобальный Google IP по TLS проходит **только при
  работающем обходе** (без обхода — таймаут), т.е. наш desync исправен, но
  бессилен против блокировки на GGC-маршруте.

Это route-class (как SYN/IP-блок): серверу реальный SNI нужен всегда, а блок
стоит на пути/у узла; ClientHello-десинк его не обходит. Практический вывод:
«страница на глобальных IP живёт, видео на GGC умирает» — если у пользователя
видео идёт по TCP к GGC, оно не пойдёт; нужен другой маршрут/QUIC/WARP.

### 2.4 QUIC/h3 — единственный живой видеопуть (высокая, но см. §2.9)

На проверенной сети QUIC-хендшейк (ALPN h3) к тем же GGC-узлам видео-SNI:
с запущенной службой — ОК (30–120 мс), с остановленной — timeout. То есть
видео живо ровно настолько, насколько жив QUIC-путь, и **держит его наш
QUIC-блок** (`fake:blob=quic_google`). TCP-fallback к GGC мёртв (§2.3).
Отсюда симптом: «QUIC не поднялся → браузер ушёл на TCP → бесконечный спиннер».
WARP помогает, потому что инкапсулирует трафик и уводит его с GGC-маршрута.

### 2.5 Внешний таймлайн (средняя-высокая)

- Сентябрь 2026 (≈1–28.09): волна SNI/IP-фильтра googlevideo, в основном один
  крупный провайдер; к концу месяца «отпустило».
- Октябрь 2026 (17–19.10+): деградация GGC/пути провайдер↔Google у нескольких
  операторов; видео играет 20–30 с / 40–80 МБ, затем 0 или 30–60 КБ/с.
- 0.10 опубликован 10.10.2026; YouTube-конфиг проекта не менялся с 27.08.2026
  (Google TCP-блок и list-google стабильны) — **внутренней регрессии 0.10 нет**.

### 2.6 0.10 vs 0.11: движок и пресеты (высокая)

- 0.10 (zip, sha256 сверены): движок zapret2 **v1.0.5**, vendor-lua 1.0.5,
  11 пресетов, `multisplit:pos=1`, QUIC-fake без repeats.
- В движке **`multisplit:pos=1` — no-op** (единственная позиция вычищается,
  «no valid split positions»): у 0.10 настоящий ClientHello с реальным SNI
  уходит целым после fake×6. Реальный split появился только в `c7aecde`
  (01.11.2026): `pos=1,midsld` — это HEAD, не 0.10.
- 0.11-черновик (архивы 27.10): движок **1.0.6**, пресеты/списки идентичны
  0.10 (отличие только CRLF→LF) — **целевых YouTube-фиксов нет**.
- HEAD (06.11): движок **1.0.7**, `pos=1,midsld`, плюс удалён дубль
  `--wf-udp-out` при GameFilter, добавлены H3-проба/DoH-fallback/DNS-профили.
- Апстрим 1.0.6/1.0.7: YouTube-специфичных фиксов в changelog нет.
- **Релиз 0.11 собирать из HEAD, а не из архивов 27.10.** Апдейтер умеет
  ставить только полный подписанный релиз, «только данные» (lists/presets)
  доставить без новой версии нельзя.

### 2.7 Тестер не проверяет видео (высокая)

- В 0.10 все YouTube-хосты исключены из `network_rate`: в скор идут только
  Discord/GitHub-записи; redirector проверяется лишь по TLS-хендшейку,
  `videoplayback`/SABR не проверяются; H3-пробы в 0.10 нет (появилась после 0.10).
- Поэтому «зелёный тестер» не доказывает работу видео, а исторические «200» —
  это HTTP-пробы страницы, не воспроизведение. В 0.11 H3-проба добавляется,
  но video-путь всё равно нужно проверять отдельной пробой.

### 2.8 Реклама/анти-адблок — не причина (низкая как причина)

- С 07.2025 YouTube не показывает рекламу РФ-профилям, а WARP+адблок —
  контрпример: видео играет, рекламы нет.
- «Fake buffering» (серверный backoff ≈80% длительности пропущенной рекламы)
  возможен только в начале/на паузе и не объясняет бесконечный спиннер;
  анти-адблок-волны 2023–2026 дают ошибку/диалог, а не спиннер.
- Слепая зона: рекламные домены (doubleclick, googlesyndication,
  googleadservices, gstatic, accounts.google.com) не покрыты ни одним списком.
  Это отдельный риск для SABR/анти-адблока, но не текущая причина.

### 2.9 Что НЕ доказано / противоречия

- **H-J:** гипотеза, что движок 0.10 (v1.0.5) не разбирает новые QUIC Initial
  (QUIC-dissect фиксы появились после 1.0.5) и поэтому QUIC-обход у affected
  не работает — **не подтверждена и не опровергнута**: manual-прогоны движков
  дают несопоставимые результаты (harness-эффект), одна проба T8 дала
  отрицательный QUIC-результат, пробы лида и T7 — положительный.
- **DNS-steering** (пин rr*-хостов на глобальные IP): TLS/HTTP открывается, но
  GET `/videoplayback` = 404 (нужен SABR POST) — **не доказан**. Все проверенные
  резолверы (системный, DoH Cloudflare/Google/AdGuard, 8.8.8.8/1.1.1.1/9.9.9.9)
  для точных rr-хостов отдают локальные GGC — смена DoH с GGC не уводит.
- **TCP-стратегии против GGC** (badsum/multidisorder/hostfakesplit/syndata/
  repeats/out-range) — окно кончилось, не проверено; ожидание: route-class
  не лечится.
- Противоречие harness: manual-winws2 с корректным conf (7 профилей) даёт
  youtube.com=200, но QUIC ведёт себя иначе, чем рабочая служба (9 профилей
  service_run.conf); причина не установлена. Для H3-выводов это учитывать.

## 3. Как диагностировать у пользователя (что просить)

1. Версия (0.10 stock?), профиль, `game_filter_mode`, браузер+версия, WARP вкл/выкл,
   вход в аккаунт, адблок.
2. DevTools → Network → фильтр `videoplayback`: колонки Method, Protocol
   (h3/http2/http1.1), Status, Size, Remote Address — скрин во время спиннера.
3. Форма симптома: (A) стартовый спиннер, запрос 0 B/canceled; (B) играет
   20–30 с / 40–80 МБ, потом 0/30–60 КБ/с (троттлинг середины потока).
4. Проверить: чистое окно/другой браузер, DoH вкл/выкл, WARP вкл/выкл,
   альтернативный пресет (multisplit-pure — реальный split pos=2).
5. Прислать ZIP «Отчёт для поддержки» из GUI 0.10 (содержит hostname/публичный
   IP — предупредить пользователя) + при возможности net-export 10–20 с.
6. Класс GGC определяется тремя наблюдениями: TCP к видео-узлу ОК, TLS-хендшейк
   к нему таймаутит, HTTP/80 к нему ОК. Тогда desync не поможет.

## 4. Рекомендации для 0.11

1. Собирать из HEAD (1.0.7 + `pos=1,midsld`), подписать, **не заявлять фикс
   YouTube** в release notes.
2. Добавить диагностику видео-пути (P0): InnerTube → signed/SABR → Range/POST
   + метрики (status/bytes/TTFB/protocol/remote IP/ASN), H3-проба, ad-проба,
   DNS-для-видео, пакет логов v2, кнопка «Собрать диагностику».
3. Вердикт диагностики должен различать: QUIC-путь не поднялся / TCP-путь к
   GGC заблокирован (route-class, fake не лечит, нужен другой маршрут/WARP) /
   реклама/PO-token/аккаунт.
4. QUIC `repeats` 6–11 для googlevideo — кандидат к A/B, не вливать без
   мультисетевого теста (текущий одиночный fake на тестовой сети работает).
5. **Не внедрять** hosts-пин/DNS-steering для googlevideo (не доказано, ротация
   rr-хостов, 404); не добавлять широкий ipset.
6. Поправить README/FAQ: совет «отключить QUIC в браузере» на GGC-сетях может
   делать ХУЖЕ — QUIC там единственный живой видеопуть; сначала проверять
   Protocol в DevTools.

## 5. Что не переоткрывать

- «Дыра» из Flowseal issue #17917 (googlevideo не в QUIC-hostlist) — у нас
  googlevideo.com в list-google и QUIC-правило Google уже использует его.
- GameFilter = «режет UDP 443»: доказано, что последний `--wf-udp-out`
  побеждает, релизные пресеты UDP 443 сохраняют; `c7aecde` — страховка для
  custom-пресетов без %GameFilter%.
- «Новый алгоритм рекламы YouTube» как корень проблемы — не подтверждён (§2.8).
- Усиление fake/split против GGC-маршрута: route-class, не лечится (§2.3).
- Отключение QUIC как универсальный совет — противоречит данным (§2.4).
