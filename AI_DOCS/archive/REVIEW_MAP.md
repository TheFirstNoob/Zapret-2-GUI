## 3. Горячие зоны (приоритеты)

### P1-a. Сборка с niquests — свежее, на чистой машине не верифицировано
Файлы: `Zapret2GUI.spec`, `build_portable.py`, `requirements.txt`.
Контекст: для QUIC-пробы бандлим `niquests[http3]` + стек.
Гипотезы к проверке (цепочки, а не «пересборка ради пересборки»):
- `urllib3_future` зеркалит себя в `urllib3/` через `.pth`; в frozen `.pth` не
  выполняется — хватит ли `collect_all` для обоих имён, и разрешится ли
  `import urllib3` внутри niquests в onefile/onedir;
- `qh3` — компилируемый pyd (abi3): попадает ли в binaries onefile;
- `h11` убран из `EXCLUDES` (нужен niquests) — не тянет ли лишний вес/конфликты;
- `wassima` на системе без ROOT-стора — корректный фолбэк CA-цепочки;
- embeddable-python в `build_portable.py`: установка `qh3` (wheel abi3, win_amd64).
Безопасная проверка: статический разбор + при наличии СВОЕЙ Windows-машины —
сборка в своей копии (НЕ на живой машине пользователя).

### P1-b. Интеграция QUIC-пробы в тестер — свежее
Файлы: `core/tester.py` — `_quic_h3_probe`, ветка `QUIC_QUIRK_DOMAINS` в
`_curl_test`, `_build_result`, `_net_stats`.
Что проверять:
- потокобезопасность ленивого кэша `Zapret2Tester._has_niquests` при параллельных
  вызовах (`_run_domain_tests` использует ThreadPoolExecutor);
- статус `H3_NONE`: все потребители (UI `statusOf` в `frontend/js/app.js`,
  `test_logger`, экспорт отчёта) не считают его провалом и не ломают вёрстку;
- бюджет времени: 5 квирк-хостов × профили × (curl 2×3с + H3 до 12с) — worst-case;
- DNS-спуф: `NameResolution` → `H3_NONE`; в тестере DoH-фолбэка нет (в tool есть)
  — намеренно ли (обоснование/риск);
- `box`-словарь и daemon-поток: **принятое ограничение** (внутренние таймауты
  `(4,8)`); открывай только при реальном сценарии «вечного» хвоста.

### P1-c. Статистика/статусы
`_build_result` (ok = только `OK`; fail = `BLOCKED/TIMEOUT/FAIL/ERROR`),
`_net_stats` (исключены control + QUIC-класс). by design: `H3_NONE` и `QUIC` —
нейтральны. Проверь, нет ли статуса, протекающего в fail/OK случайно, и нет ли
расхождений между списками статусов в разных местах кода.

### P2-a. Dev-инструменты (`tools/`)
`quic_probe.py`, `upload_probe.py`, `tls_ver_probe.py` — свежие, живьём проверены
(ya.ru/CF/i.ytimg). Ищи: парсинг аргументов/URL, UNSUP-детект под Schannel,
временные файлы, крайние таймауты. РАСХОЖДЕНИЕ ПО ЗАМЫСЛУ: `upload_probe`
трактует «полный upload + 0 download + время на пределе» как `LIKELY_BLOCKED`,
а тестерный `_tcp1620_test_curl` — как `OK` («поток не резан») — это осознанно
разные инструменты; проверь лишь, что это не конфликтует в отчётах/доках.

### P2-b. Апдейтер/релизный контур (не свежий, критичный)
`core/updater.py`, `tools/release_publish.py`, `tools/security/*`. 0.10 не
аудировать; общие механики (откат, путь-траверсал в архивах, подпись, sha) — если
остался бюджет.

### P3. Доки/UI
Консистентность README ↔ код (3 состояния QUIC), подписи, AGENTS-нюансы.

## 4. Карта проекта

- Entry: `main.py` (WebView2+pythonnet, single-instance, MOTW-strip).
- Сервер: `server/server.py` (локальный HTTP API) ↔ `frontend/js/app.js` (UI).
- Ядро: `core/tester.py` (главный), `core/launcher.py` (сборка args/запуск
  winws2), `core/service_manager.py`, `core/collector.py` (диагностика/экспорт),
  `core/updater.py`.
- Движок: `bin/winws2.exe`, `lua/`, `blobs/`, `presets/`, `lists/`, `hosts.txt`,
  `windivert/`.
- Сборки: `build.py`, `build_portable.py`, `build_lite.py`, `Zapret2GUI.spec`,
  `requirements.txt`.
- **Автотестов В РЕПО НЕТ** (harness'ы локальные, gitignored) — не ищи `tests/`.
- Доки: `AI_DOCS/` (AGENTS — главная память; этот файл — навигация ревью).

## 5. Как проверять безопасно

Разрешено:
- `python -m py_compile <файл>`; статический анализ; чтение кода.
- Прямые unit-вызовы `Zapret2Tester._curl_test(...)` / `_quic_h3_probe(...)` из
  своего скрипта — службу не трогают (пример в коммите e7a4b4b/87d498b).
- `tools/*_probe.py` на безопасных целях: `ya.ru`, `cloudflare.com`, `i.ytimg.com`.

Запрещено / осторожно:
- **НЕ** запускать полный прогон тестера — он перезапускает службу `zapret2`
  (живая сеть пользователя!).
- **НЕ** менять system `hosts`, службу, сетевые настройки, WARP.
- **НЕ** коммитить/пушить; **НЕ** запускать `build_portable.py` на живой машине.
- Любой эксперимент — только в СВОЕЙ копии/песочнице; эта машина — рабочая.

Среда (факты): Windows 11, Python 3.13, `curl 8.21 Schannel` (H1-only), winws2
v1.0.5 (runtime) / исходники zapret2 v1.0.2 локально, venv `niquests 3.21.2 +
qh3 2.0.4` (локально `%TEMP%\opencode\h3env`).

## 6. Формат отчёта

Сгруппируй по severity. Для каждой находки: 1-2 строки сути → `файл:строка` →
цепочка → репро/аргумент → минимальный фикс → риск регрессии → «доказано/гипотеза».
Отдельный раздел: «гипотезы, требующие Windows-машины» (что именно нужно).
