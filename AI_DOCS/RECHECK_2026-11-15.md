# Recheck 0.11 — полный прогон 2026-11-15

> База: опубликованный 0.11 (`Pre-Release-0.11` = `f29cdb3`, HEAD `8fec12f`).
> Инцидент: на чистой Windows 11 установка службы падала с
> `winws2 --intercept=0 rc=3: windivert: error opening filter: the system
> cannot find the path specified`; 0.10 работал. Пользователь разрешил live-
> проверки на своём ПК.
> Результат: 6 независимых статических аудитов + live-матрица; P0/P1
> исправлены, 0.11.1 собран из `69869b5` и опубликован 2026-11-15:
> https://github.com/TheFirstNoob/Zapret-2-GUI/releases/tag/Pre-Release-0.11.1

## Вердикт

В опубликованном 0.11 есть **два P0**, которых не было в 0.10:
1. `start(None)` (repair/«Выгрузить драйвер», восстановление после тестера,
   updater, session-recovery, миграция 0.10) ломался на разборе
   `service_run.conf`: многострочный conf читался парсером одной cmdline.
2. fail-closed `winws2 --intercept=0` до починки WinDivert блокировал
   install/start на машине с мёртвой/чужой службой драйвера или удалённым
   `.sys`; текст ошибки совпал с инцидентом. В 0.10 rc этого preflight
   игнорировался.

Оба класса закрыты в main и выпущены в **0.11.1** (`69869b5`). Live-матрица на этой машине:
stop/start/restart/repair/remove/install — все операции снова проходят,
служба возвращается в RUNNING; DNS apply/reset — OK. До выпуска 0.11.1
остаются P2/P3 (ниже) и пересборка/подпись/публикация.

## Что исправлено в main

- **P0 service conf**: `core/launcher.read_run_conf` (токен на строку) вместо
  `split_windows_cmdline`; `start(None)` больше не отвергает свой conf.
- **P0/P1 WinDivert preflight**: `prepare_engine_environment` до проверки
  (repair stale-драйвера + SeLoadDriverPrivilege), проверка файлов
  `winws2/cygwin1/WinDivert.dll/WinDivert64.sys`, а rc≠0 с windivert-маркером
  классифицируется как ошибка среды, а не Lua; реальные Lua/arg-ошибки
  остаются fail-closed. Direct-start («Запустить» без службы) готовит
  окружение до `validate_args`.
- **P2 repair**: `resolved=false` и `restart_failed`, если служба не поднялась.
- **P2 update**: ошибка рестарта после portable-апдейта больше не глотается;
  UI показывает предупреждение.
- **P2/P1 tester**: early-return `blob_probe` при Zapret 1 освобождает
  operation-lock; между блобами гасится winws2; `engine_broken` показывает
  реальный stderr (в т.ч. WinDivert).
- **P2 settings update**: импорт сохраняет вложенные USER_FILES
  (`list-games`/`list-include-all`); backup переживает mtime < 1980.
- **P2/P3**: диагностика не валит чек «Пресет» из-за драйвера; CDN не создаёт
  конфликт include/exclude молча; DNS active-profile сравнивает семейства
  v4/v6; sign-гейт fail-closed без версии движка; `check_arg_file` не считает
  SKIP успехом; security-заголовки index; UX-тосты службы; lite
  service-install проверяет sc create/start.
- **Тесты**: 329 passed, security 47 (direct runner 47); live service
  stop/start/repair/remove/install; DNS apply/reset.

## Остаточные P2/P3 (не блокеры, но кандидаты в следующие патчи)

- ProcessProbe: глобальный `pktmon` и фиксированные temp-имена (вторая копия
  GUI/сбой может оставить захват без stop).
- CDN `_resolve_many` глотает исключения (protection-множество неполное);
  `api_cdn` при OSError может дать 500; нет переносов include↔exclude —
  теперь явный отказ с просьбой убрать конфликт.
- DNS backup может быть от другого адаптера (stale backup).
- pktmon-сбой в ProcessProbe показывается как «UDP-сокеты не найдены».
- `_sc_run_bat` — предсказуемый `%TEMP%` bat (P2/P3 hardening),
  `_win32_advapi` без кэша, статус PENDING→stopped.
- Тестовые дыры: WinDivert-хелперы/ProcessProbe lifecycle, release-гейты
  (нет unit на classify/sign), api_smoke негерметичен при stale crash-журнале.
- lite содержит сгенерированные built-in games/list-include-all — это
  **нужно** для start-*.conf, не удалять (замечание ревью ошибочно).
