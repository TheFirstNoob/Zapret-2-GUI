# План: WebView2 fallback при белом экране

> Статус: **preflight + auto/`--browser` Edge/Chrome реализованы 2026-10-24**.
> Fixed Version Runtime в архив не бандлится; проверка на чистом Win10 без
> WebView2 ещё нужна. Триггер: у пользователя Win10 без WebView2 Runtime
> pywebview молча ушёл в MSHTML/IE — окно белое, интерфейс не рендерится.
>
> Реализация: `main.py` проверяет registry/env/Program Files, при отсутствии
> Runtime и наличии Edge/Chrome открывает `--app=` с отдельным временным
> профилем; `--browser`/`ZAPRET2_BROWSER=1` форсирует режим. Нет браузера —
> MessageBox со ссылкой. Сервер живёт, пока жив процесс браузера.
> Ограничения: браузер запускается с теми же правами (обычно admin), токен
> остаётся в URL, нет нативного события закрытия вкладки. Это оставшиеся
> пункты ниже, не блокирующие базовый fallback.

## 1. Проблема

- GUI — HTML/CSS/JS, на Windows рендерится pywebview через WebView2.
- Нет WebView2 → pywebview может упасть в MSHTML (IE): современный фронт
  не работает, получается белый/пустой экран.
- `main.py` ловит только ImportError и исключение `webview.start()`;
  preflight-проверки Runtime и .NET нет.
- README сейчас говорит, что WebView2 «встроен в Win10/11» — неточно:
  в Win10 его может не быть (LTSC/старые сборки/Edge удалён).

## 2. Цели / не-цели

**Цели:**
1. Не показывать белый экран: либо понятное сообщение + ссылка, либо
   рабочий fallback.
2. Сохранить ядро/службу/HTTP-сервер без изменений.
3. Не ломать основной путь с WebView2.

**Не-цели:**
- Переписывать UI на Qt/Tk/CEF.
- Бандлить Fixed Version Runtime в основной архив (сотни МБ) без отдельного
  решения.
- Обещать нативное окно/трей/горячие клавиши в браузерном режиме.

## 3. Варианты

### A. Preflight + понятная ошибка (минимум, первым)
- Проверить WebView2 Runtime (registry `EdgeUpdate\Clients\
  {F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` / `pv`), .NET >= 4.6.2,
  импорт pywebview.
- Если нет — MessageBox с кнопкой/ссылкой на Evergreen WebView2, затем
  выход (или предложить browser fallback, если он уже готов).
- Дёшево, безопасно, убирает «белый экран без объяснения».

### B. Browser fallback (основной запасной режим)
- Запустить локальный сервер, дождаться готовности, открыть
  `http://127.0.0.1:<port>/?token=...`.
- Предпочтительно Edge/Chrome в app-режиме:
  `msedge.exe --app=<url>` / `chrome.exe --app=<url>` (+ размер окна).
  Если нет — обычная вкладка браузера по умолчанию.
- Браузер должен быть современным (Chromium/Firefox); IE/старый Edge —
  не подходит, показать требование.
- Фронт уже не использует `pywebview.api`, только HTTP/localStorage —
  технически миграция реальна.

### C. Бандл Runtime (позже, по необходимости)
- Evergreen Bootstrapper (~2 МБ, качает Runtime) или Fixed Version
  (~100+ МБ, офлайн). Вопрос размера/обновлений/AV — отдельно.

## 4. Обязательные детали fallback

- **Lifecycle:** в браузере нет события закрытия нашего окна. Нужен
  heartbeat/`pagehide`/`sendBeacon`; решить, завершать ли процесс после
  закрытия вкладки или оставлять службу.
- **Single instance:** повторный запуск не должен плодить серверы/вкладки;
  фокус существующей вкладки браузер гарантировать не может.
- **Токен:** сейчас `?token=` попадает в историю/синхронизацию браузера.
  Для fallback — одноразовый код/кука/фрагмент + `Referrer-Policy:
  no-referrer`; после обмена убрать из URL.
- **Безопасность:** loopback + Host allowlist + CSP; браузерные расширения
  получают доступ к странице; не запускать браузер elevated из-под админа;
  рассмотреть отдельный user-data-dir (без расширений/синка).
- **UX:** баннер «Режим браузера», кнопка «Открыть снова», ограничения
  (загрузки/диалоги/размер окна — браузерные).
- **Совместимость:** локальный HTTP на localhost — secure context; но
  корпоративные политики/прокси/расширения могут мешать `/api`.

## 5. Тесты

- Win10 22H2 без WebView2 + Edge/Chrome/Firefox/IE-default.
- Win11 с WebView2 (регресс: используется встроенное окно).
- Нет современного браузера → понятное сообщение.
- app-режим Edge/Chrome; обычная вкладка; закрытие вкладки/процесса.
- Повторный запуск, single instance, сервисный режим.
- Токен: история/Referrer/синхронизация; чужой origin.
- Загрузки, файловые диалоги, буфер обмена, уведомления.
- Portable/EXE; запуск от админа; AV/политики.

## 6. Порядок внедрения

1. Preflight WebView2/.NET + README/FAQ + диагностика (без fallback).
2. Browser fallback за флагом (`--browser`/env) → обкатка.
3. Автовыбор fallback при отсутствии WebView2; Edge/Chrome `--app`.
4. Решение по бандлу Runtime — только после замеров размера/жалоб.

## 7. Критерий готовности

- На машине без WebView2 пользователь не видит белый экран: либо установка
  Runtime по ссылке, либо рабочий UI в современном браузере.
- Основной путь с WebView2 не изменился; тесты выше пройдены.
- README/диагностика честно сообщают зависимость и способ лечения.
