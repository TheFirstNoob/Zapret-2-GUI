# Стратегический роадмап: модификаторы, протокол валидации, границы

> **Обновлено: 2026-09-13.** Читается вместе с STRATEGY_GUIDE и STRATEGY_TRIALS.

## 0. Пять принципов (утверждено)

1. **Один параметр — одна гипотеза о DPI.** Параметр без гипотезы не добавляется;
   лишний параметр = микрозадержка, размер пакета, риск нестабильности.
2. **Модификатор встраивается в вызов при построении пресета**, а не дописывается
   в конец цепочки (в конце он неотличим от нуля — tcp_md5 в конце = мусор).
3. **Пользователь не получает модификаторы** — только стратегию (пресет), свои
   списки, тогглы. Параметры пресетов — зона разработчиков.
4. **Кандидат обязан пройти CDN A/B** — не «пробивает больше всех», а «пробивает
   цели и не глушит то, что живо без десинка».
5. **Сегментация `--new` — правильная архитектура пресета.** Каждый сервис
   (Discord Voice/Media/TLS, Google TLS, General TCP, QUIC Google/General) —
   свой блок со своими фильтрами и цепочкой. Смешивание победителей по блокам
   легитимно (так работает build_custom).

## 1. Механика модификаторов (механизм → когда помогает → цена)

| Модификатор | Механизм | Когда помогает | Цена / статус |
|---|---|---|---|
| `tcp_md5` (RFC 2385) | легитимная сигнатура (BGP), DPI часто пропускает/ломается | DPI, фингерпринтящий TLS по TCP-опциям | +18 байт/пакет; старые middleboxes дропают. ✅ полигон + 100% Т2 (tcpmd5-fake), кандидат №1 |
| `ip_autottl` | фейк доживает до DPI и умирает до сервера; сам подстраивается под глубину ТСПУ (фиксированный ip_ttl не умеет) | fake-зависимые DPI | при неудачном delta фейк доходит до сервера. Стандарт: `-2,3-20` / `-1,3-20`. ✅ cand-autottl: 100% Т2, 0 расхождений |
| `tcp_ts` / `tcp_ts_up` | DPI, валидирующий монотонность TS, дропает фейк с TS в прошлом; tcp_ts_up для Linux-серверов (наши цели редко) | TS-валидирующие DPI | требует включённые timestamps (tcp_timestamps.py делает при старте). ⚠️ только на fake — multisplit умирает по PAWS |
| `tls_mod: rnd/rndsni/dupsid/sni=` | статический блоб = статический фингерпринт; rndsni — случайный SNI, dupsid — session_id из реального hello | DPI, маркирующий статичный фейк | при whitelist-DPI случайный SNI = признак → нужен «белый» блоб. cand-rndsni 84.6% Т2; побочка — меняет блоб глобально |
| `seqovl (+pattern)` | «скрытый фейк»: мусор-префикс уходит за окно по seq, DPI читает как данные, сервер отбрасывает | широко | паттерн «белый» (google_tls) — уже в default |
| `ipfrag` | фрагментация на IP-уровне; DPI без reassembly не видит SNI | безreassembly-DPI | часть сетей режет фрагменты вообще; NAT-глюки. Только exp- |
| `syndata (+send:repeats=2)` | ClientHello внутри SYN до handshake | классификация DPI сбивается | без `--ipcache-hostname` + DNS-перехвата не работает точечно; на Т2 30-46% вслепую. Только отдельным пресетом |
| `udplen` | раздувание UDP-пейлоада; DPI с привязкой к длине (Discord voice) промахивается | Discord voice | только в блоке Discord Voice; цена ≈ 0 |

## 2. Протокол валидации кандидата (обязательный)

Кандидат = копия default с ОДНИМ изменением (контроль переменных). Пути:
`presets/cand-*.txt` (скрыты из GUI `_ui_presets`).

1. **Fail-набор:** тестировать на доменах, которые база НЕ пробивает
   (blocked_domains лучшей стратегии). На чистом окне разницу не измерить.
2. **Полигон (pkt_verify):** механическая проверка, что параметр реально вышел
   в пакеты (MD5-kind 19, TTL, размер), а не «перекрыт другим модификатором».
3. **CDN A/B:** кандидат, который чинит цель, но добавляет DET в fix-классе —
   отклоняется.
4. **Окно стабильности:** 2+ сети, время наблюдения. Одиночная сеть = пометка
   «для сетей, где X», не дистрибутив.
5. **Результат → строка в STRATEGY_TRIALS.** Проигравший пресет не удаляем.

## 3. Кейс «два ПК в одной Wi-Fi глушили друг друга» (Zapret 1)

- Локально машины interference дать не могут: WinDivert перехватывает только
  свой трафик, LAN-трафик соседа отсечён `--wf-filter-lan=1`.
- **Реальная точка — ТСПУ/абонентский уровень:** оба ПК за одним NAT = один
  публичный IP; DPI ведёт пер-IP статистику — аномальные пакеты с двух машин
  суммируются и меняют классификацию всего адреса. Отсюда «глушили сами себя».
- Вторичный фактор — домашний роутер (фейки с низким TTL умирают на первом
  хопе; роутер с DPI может реагировать).
- Заплатка в GUI: диагностический чек «Другие устройства в сети»
  (`_check_lan_peers`, ARP-кэш, всегда ok — информирует). Правильная практика:
  **одна и та же, наименее агрессивная из рабочих стратегий на всех машинах.**

## 4b. Запасной план против «гонки репитов» — ЗАКРЫТ на Т2 (2026-09-10)

**Проблема:** repeats — тупиковая гонка: DPI рано или поздно научится маркировать
«всплеск одинаковых пакетов» (rawsend_rep шлёт байт-в-байт копии), эскалация
выигрывает у DPI.

**Батарея не-репитных кандидатов (Т2):** test-nodrop-mod (tls_mod=rnd,dupsid),
test-clone, test-oob, test-rstdesync — **все 000**; test-snifirst — 200.
**Вывод (по pktmon):** DPI анализирует СЕССИЮ целиком (tspu-docs 23.1); решает
**объём/доля google-фейков ≥90% в начале сессии**, не идентичность и не
разнообразие (repeater 7 разных фейков = 000, ip_id=zero идентичные = 200).
Discord на Т2 жёстко требует repeats — единственный рабочий механизм сейчас.
Не-репитные пресеты НЕ удаляем — кандидаты для сетей без вероятностного
счётчика.

## 5. Что НЕ делаем (и почему)

- IP-блоки (MTProto/Telegram, Facebook) — вне зоны движка; путь — hosts.txt.
- Break-класс CDN (DO/Hetzner/OVH/Vultr/BuyVM) — любой десинк вредит
  (STRATEGY_TRIALS, 2026-09-03). Не «стабилизируем».
- Комьюнити-пресеты вслепую — репо на API v0.9 (compat 5), подтверждённые баги
  (ttl_ladder, seqovl_white, дубли http_methodeol_safe, instance_cutoff).
  Только порт отдельных техник с фиксом.
- wssize, oob, synack* — «крайние средства»: только exp- (wssize режет скорость;
  oob требует старт с SYN, несовместим с сегментаторами).
- Вероятностные оркестраторы (cond_random) в пользовательских пресетах —
  нестабильность для пользователя; зона экспериментов.
