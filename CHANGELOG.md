## Pre-Release 0.12 (2026-11-18) — Discord/Cloudflare fix

### Главное

- **Мастер Discord/Cloudflare**: кнопка/уведомление на Главной и карточка в «Диагностике» — проверка hosts, случайный health-checked IP из пула, hosts + NRPT + локальный scoped-DNS, включение/отключение/смена IP.
- **Auto-режим**: задача Планировщика Windows `Zapret2GUI DiscordFix` с триггером Boot, SYSTEM, запускает тот же python/exe с `--discord-fix-helper`; GUI можно закрыть, helper переживает перезагрузку. Путь задаётся в задаче, а не в ImagePath службы.
- DNS отвечает только для Discord/Cloudflare/auth-зон; системный DNS не меняется. Candidate IP выбирается на сессию (не на каждый запрос) и проверяется TLS перед применением.
- В пул входят Cloudflare-auth/captcha домены: `cloudflare.com`, `cloudflareaccess.com`, `challenges.cloudflare.com`, `auth0.com`, `epicgames.dev`, `fandom.com`.
- Данные: `lists/discord-candidates.json` (252 IP), состояние и backup hosts в `logs/discord_fix_*`.
- Ограничение: это временный обход, не VPN. При блокировке пула — WARP/другой маршрут.
- Lite (engine-only) не содержит Python/helper и этот fix не поддерживает; только portable/EXE. В Lite base-hosts без dynamic/voice.

### Исправлено

- Ложная «DNS-подмена» в диагностике: активный hosts-пин Discord больше не выдаётся за подмену DNS; чек показывает предупреждение и не советует менять DNS.
- README: добавлен раздел `[Warning] Discord после 18.11.2026` с объяснением и ограничениями.

### Тесты

- 354 passed; live-enable/rotate/disable с реальными hosts/NRPT/DNS: Discord API 200, challenges 200, auth0 200, Cloudflare 301, rotate 200; отключение убирает hosts-блок и NRPT, hosts восстанавливаются.
- Task Scheduler: install/query/start/remove и реальный `--discord-fix-helper` под SYSTEM: task RUNNING, порт 53 слушает helper, DNS-зоны резолвятся в candidate; повторный enable после disable — OK.
- При старте helper/GUI — один TLS health-check сохранённого IP; при провале выбирается новый.
- Исправлен atexit-баг: Python-процесс больше не снимает NRPT, если helper работает как задача (`mode=task`); путь задачи сохраняется в state и переустанавливается при переносе приложения.

## Pre-Release 0.11.1 (2026-11-15) — исправления службы и восстановления

### Исправлено

- **Внутренний `start(None)`** (восстановление защиты после тестера,
  «Выгрузить драйвер», updater после обновления, session-recovery, миграция
  0.10) больше не отвергает свой `logs/service_run.conf`: многострочный conf
  читается построчно, а не парсером одной командной строки. В 0.11 это
  ломало восстановление службы и оставляло обход снятым.
- **Установка/запуск на машине с неисправным WinDivert**: перед preflight
  программа ремонтирует/убирает старую битую службу драйвера, включает
  SeLoadDriverPrivilege и проверяет файлы `winws2/cygwin1/WinDivert.dll/
  WinDivert64.sys`. Ошибка `--intercept=0` с windivert-маркером теперь
  классифицируется как ошибка среды (как в 0.10), а не как ошибка Lua;
  реальные ошибки Lua и аргументов остаются fail-closed. Это устраняет
  регрессию 0.11 `windivert: error opening filter: the system cannot find the
  path specified` при установке службы.
- **Кнопка «Запустить» без службы** готовит драйвер до той же проверки.
- **«Выгрузить драйвер»/repair** больше не рапортует `resolved=true`, если
  служба не поднялась; добавлен `restart_failed`.
- **Portable-обновление**: ошибка повторного запуска обхода не глотается
  (UI показывает предупреждение); backup не падает на mtime < 1980;
  импорт настроек не теряет `list-games.txt` и `list-include-all.txt`.
- **Тестер**: «Перебор блобов» при запущенном Zapret 1 больше не оставляет
  занятым глобальный operation-lock; между блобами гасится старый winws2;
  `engine_broken` показывает реальный stderr движка (включая WinDivert/AV).
- **Диагностика/данные/UI**: чек «Пресет» не краснеет из-за драйвера; CDN не
  создаёт молча конфликт include/exclude; DNS-профиль сравнивает v4/v6 по
  семействам; sign-гейт fail-closed без версии движка; `check_arg_file` не
  считает SKIP успехом; security-заголовки index; аккуратные тосты установки
  службы; lite `service-install.bat` проверяет `sc create/start`.
- **Тесты**: 329 passed, security 47; live-матрица службы
  (stop/start/restart/repair/remove/install) и DNS apply/reset — OK.

## Pre-Release 0.11 (2026-11-14) — опубликован

### Главное

- **Движок winws2 обновлён до 1.0.7** (в 0.10 — 1.0.5): QUIC-диссекция и
  исправления 16–20 КБ; stock-lua `lib/antidpi/auto/obfs` синхронизированы,
  наш `zapret-custom.lua` сохранён. Пресеты используют корректные маркеры
  `multisplit:pos=1,midsld`; одиночный `pos=1` также валиден (маркеры zero-based; уточнено 2026-11-24).
- **DNS-профили** — быстрая смена системного DNS на Главной: два профиля
  (Основной/Резервный), до двух серверов в каждом, шаблоны Google/Cloudflare/
  Quad9/Comss или свои адреса. Применение только по кнопке, исходный DNS
  сохраняется, «Вернуть системный DNS» восстанавливает его.
- **Единый блок на Главной**: обход/стратегия, служба и DNS-профили — в одной
  карточке; статус всегда в шапке, действия — отдельной строкой, опасные
  операции (выгрузка драйвера, удаление службы) убраны в «Ещё…».
- **Настоящая QUIC/HTTP3-проверка** тестера для «квирк»-хостов (forced H3,
  проверка `version=30`, дедлайн 6 с, отмена потока); статус «H3 не подтверждён»
  нейтральный. Без `niquests` остаётся прежняя эвристика.
- **Запуск без WebView2 Runtime**: preflight проверяет Runtime; если его нет —
  GUI открывается в Edge/Chrome в app-режиме (`--browser`), вместо белого
  экрана или MSHTML.
- **Portable-обновление с runtime**: манифест везёт `python/**` (niquests/qh3),
  распаковка в `python.new`, атомарное переключение после выхода GUI и
  post-check версии/файлов с rollback. Для обновления 0.10→0.11 portable
  нужно один раз переустановить из архива (см. «Ограничения»).

### Добавлено

- **Главная**: один блок «обход + служба + DNS»; понятные статусы и
  контекстные действия, DNS-форма с подписями полей.
- **Списки**: подробная диагностика конфликтов — домен, в каком файле
  (`ваш` / `системный`), что именно сделать; диалог «Убрать дубли» объясняет,
  что удалит и что конфликты автоматически не трогает.
- **ASN-скан**: необязательный SNI для проб (по умолчанию `example.com`),
  per-item SNI из набора, HTTP-пробы по своим портам, корректная классификация
  OK/12 КБ; закреплённый снимок данных и инструмент синхронизации.
- **Служба**: durable-журнал операций (`logs/service_op_state.json`) с
  восстановлением/откатом при старте GUI после падения; отключение SCM-recovery
  перед удалением; подтверждение отсутствия службы; ожидание смерти winws2 по
  PID/пути через `WaitForSingleObject`.
- **Тестер/диагностика**: бюджет TCP16-20 под скорость аплинка (нет ложных
  DETECTED на медленном канале); отмена батареи с частичными результатами;
  probe-файлы только в `runtime/probe` (в релиз/диагностику не утекают);
  per-check guard диагностики; DNS-backup со всеми v4/v6 адресами.
- **Обновления/релиз**: fail-closed проверки `sign_release`/`release_publish`
  (полнота трёх архивов, версия/тег/PUBKEY/движок, подпись, sha256/size);
  проверка обновлений показывает только опубликованную версию, а не draft.
- **Производительность**: Toolhelp32/`QueryServiceStatusEx` для статуса
  (~0.02 мс кэш против tasklist 116 мс), объединённый PS-вызов ProcessProbe
  (−52% запусков PowerShell), DNS-status ≈0.8 с вместо 3.4 с, кэш конфликт-скана.

### Изменено

- **«Своя игра» проще**: поле процесса убрано из формы custom-игры; у
  встроенных игр процесс сохранён для «Анализа приложения»; старые данные не
  затираются.
- **Длинные пути и служба**: запуск и служба — через `@conf`; пробелы и
  кириллица в пути больше не упираются в лимит командной строки; binPath
  короткий, старые установки мигрируют; lite переведён на conf; 8.3 — только
  аварийный bat-фолбэк.
- **Служба и обновления**: изменяющие операции сериализованы; stop ждёт
  реального `STOPPED`; обновление ограничено по времени/размеру, portable
  откатывается при сбое; импорт настроек ограничен по распаковке.
- **UI**: главная собрана в один блок; статусы/действия упорядочены;
  восстановление контролов анализа после сбоя, защита legacy-полей Zapret 1.
- **Lite**: `start-*.bat` не запускает второй winws2; `stop.bat`/
  `service-remove.bat` трогают только свою службу `zapret2` и движок из своей
  папки; `service-install`/`service-remove` отказываются от чужой службы;
  добавлены `fix-driver.bat` и `update.bat` (только уведомление).
- **Wardogs**: UDP 4192–4194 (включая региональные 4193/4194; 4129 — опечатка).
- **Hosts**: добавлены пины погодных API, убраны мёртвые Twitch-пины;
  `hosts.txt` лежит во всех трёх сборках.
- **Имена архивов в Releases**: только pretty-имена
  (`Zapret2GUI-Full-PyInstaller.zip`, `Zapret2GUI-portable-Recommended.zip`,
  `Zapret2GUI-lite-CMD.zip`); канонические имена остаются в git/jsDelivr.

### Исправлено

- **Обновление EXE при работающем обходе** больше не ломает запуск: перед
  заменой данных своя служба/winws2 останавливаются, копирование с ретраем,
  служба возвращается, маркер версии не пишется при провале.
- **Валидация аргументов** стала fail-closed: отказ winws2 (`rc≠0`), дубли
  list-файлов, `wf_priority` вне диапазона и пр. больше не считаются «OK».
- **Operation-lock**: нельзя освободить чужую операцию; `blob_probe`/
  mutating-ручки корректно сериализуются; битый JSON даёт 400, а не `{}`
  (раньше `/api/dns/apply` мог применить дефолты).
- **Служба**: `repair` больше не ложно требует перезагрузку; служба из
  удалённой папки получает состояние `orphaned` и лечится переустановкой;
  внутренний `start` проверяет `service_run.conf`; remove на SCM-recovery не
  оставляет службу удалённой; восстановление после падения GUI.
- **Тестер**: стабильные таймауты скоринга (не 2 c); TCP16-20 на медленном
  аплинке — TIMEOUT, а не ложный stateful-DPI; H3 не оставляет поток-сироту;
  отмена сохраняет частичные результаты; `engine_broken` показывает причину.
- **Диагностика/данные**: одно исключение не убивает весь отчёт; DNS сравнивает
  только семейства профиля (ложный откат IPv4+IPv6 убран); `reset` возвращает
  все DNS; гонка `games.json` закрыта локом; CDN-стабилизатор пишет в
  user-списки, а не в bundled; conflict_scan видит запущенные службы.
- **Списки/UI**: конфликты показывают домен/файл/действие; подтверждение
  dedupe объясняет, что удалит; правки списков/конфига во время теста получают
  409; GameFilter больше не расширяет окно чужого протокола; типы конфига
  нормализуются; `fake_blob` работает во всех `--lua-desync`.
- **Безопасность**: Ed25519 отклоняет неканонические подписи; токен сравнивается
  constant-time; тело запроса ограничено; завершение winws2 фильтруется по пути.
- **Игры**: проверка доменов ограничена по времени; битый `games.json` уходит в
  `.bad` и не затирается.
